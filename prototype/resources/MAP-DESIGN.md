# 关卡与地图设计规范

地图采用独立数据资源，玩法参数放在 game-config.js；新增地图后在 index.html 中加载，在 campaign.js 的 CAMPAIGN_LEVELS 中登记顺序。

## 布局原则

1. 当前关卡使用一个出怪点、一座基地、一条连续路线，无分岔。路径由水平或垂直拐点组成，不出现斜线、交叉或重复路段。
2. 出怪点与基地均为地图内部点，四周距地图边界至少 **4 格**。这部分是景观和视野缓冲，即便没有战斗用途也必须保留；不得让道路终点充当地图边缘。
3. 终点周围还要预留基地和旗帜的绘制空间。靠近地图边界的景物不应遮挡路径、矿石或建筑信息。
4. initialCamera.focus 指定开局观察中心，优先覆盖出生点和初始矿区；出生标记要避开顶部 HUD。镜头原有边界和最小缩放限制继续生效，任何视口不得露出场外。
5. 起点区域必须有可采矿格和至少数个不占矿石、不占道路的采矿机位置；相邻矿区提供扩张选择。不要将资源全部放在基地附近或无战斗意义的角落。
6. 矿石不能重复、越界或落在道路上。每块容量贡献仍为 6，最多 5 台计入；矿石总数增加会直接提高全关容量上限，应谨慎调整。
7. 更大的地图应增加有用的折返、防守区和资源选择，不通过增加空白直线单纯延长等待。

## 关卡资源字段

- id、label：关卡编号和 HUD 名称。
- width、height、cellSize：地图尺寸和单格边长。
- edgePadding：设计要求的出生点、基地最小留白格数。
- initialCamera.focus：开局观察中心 [列,行]，会受合法镜头边界限制。
- paths：路径拐点数组，首点出怪、末点基地；当前仅一个元素。
- oreClusters：矿区分组坐标。
- allowedBuildings：本关可建造建筑 ID 和菜单顺序，2/3/4 项对应独立绘制模板。
- rules：本关覆盖 game-config.js 默认规则的字段，例如 initialDelay 和 batches。
- reward：通关获得的建筑介绍，含 building、title、description；无奖励时为 null。
- terrain、grassVariants、spawnMarker：地形与标记资源，可复用第一关。

## 刷怪与推进

小批次由 rules.batches 定义；每批逐个生成，本批全部生成后，击杀数达到 trigger.kills 或最远推进达到 trigger.progress 就接下一批，允许敌人重叠；清场也可接下一批。assault:true 表示一次总攻，不等同于普通批次。重甲不在开场出现。

最终批次清场且基地存活才胜利。胜利展示本关奖励与下一关入口；进入下一关重新初始化建筑、容量、CD、生命与批次，不继承上一关战场。重新开始只重置当前关卡。通关记录尽力保存在本地，存储不可用时不影响继续游戏。
